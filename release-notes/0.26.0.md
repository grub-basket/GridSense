## 0.26.0 — reorder properties in many notes at once, with saved orders

## Highlights

- **Reorder properties in notes.** Put the properties of a whole folder (or the entire vault) in the order you choose, so they appear that way in Obsidian's Properties view. Only the order changes; values stay the same, and notes that are already in order are left untouched.
- **Start from the grid.** Open it from the new **↕ key order** toolbar button, a column header's **Apply column order to notes…**, the columns & views window, or the command palette (**Reorder properties in notes**). The list starts in the grid's current column order.
- **Choose what happens to the rest.** Properties you don't list either go after the listed ones or stay exactly where they are.
- **See it before you apply it.** The window shows how many notes will change, asks before changing more than 200, and the whole run is one undo step.
- **Saved orders, with backup.** Save named orders, load them later, and export or import them from **Settings → Property orders**. The export file uses a shared format that **Bases Toolbox 0.1.71** imports too, so the same saved orders work in both plugins.
- **Heads-up:** Obsidian rewrites the frontmatter block when it saves a note, so quoting, spacing or list style in the YAML may be normalized, and **comments inside the frontmatter are dropped**.

## All changes

### 0.26.0

- **New "Reorder properties" window** (`src/reorder-modal.ts`).
  - **Notes:** "This folder" covers the open grid's folder, including subfolders, the same notes the grid uses. "Entire vault" covers every markdown note. Without an open grid, only the entire vault is offered.
  - **Ordered list:** the grid's frontmatter columns come first, in their current order. File, file-info, heading and formula columns are skipped because they are not stored in the note. After them come the other properties found in those notes, most common first.
  - **Each row** shows how many notes have that property, a drag handle, up/down buttons and a remove button ("don't manage this key"). Alt+↑/↓ moves the focused row, and focus follows the moved row.
  - **Add a property** puts a removed or unseen property back, with autocomplete. A reset button starts the list over.
  - **Properties not in the list:** "Go after the listed ones" (the default, set in settings) or "Stay where they are". The second keeps unlisted properties in their exact slots and fills the slots the listed ones used, in list order.
  - **Live count** of how many notes will change. A note that lacks a listed property simply skips it, and notes already in order are not written.
  - **Apply** asks first above 200 notes, shows progress, and runs as one undo step. Opened from a grid, it goes on that grid's undo (⌘Z / ⎌ undo). Opened without a grid, the result notice has an **Undo** button for that run, and the new **Undo last property reorder** command undoes the latest one. Undo and redo report any note that was renamed, moved or deleted in the meantime.
- **New entry points:**
  - the **↕ key order** toolbar button;
  - **Apply column order to notes…** in the column header menu;
  - **Apply to notes…** next to "Reset to note order" in the columns & views window;
  - the **Reorder properties in notes** command.
- **Saved property orders** (`{ name, keys, unlisted }`), stored in the plugin settings. The window offers **Save as…** (asks before replacing a same-named order), a **Load** menu, **Update** and **Delete**.
- **New settings section "Property orders"** (`src/property-order-settings.ts`):
  - the default for unlisted properties;
  - the saved orders, each with rename and delete;
  - **Export**, which copies the JSON to the clipboard and saves it to a vault file (default `property-orders.json`, path autocompleted, asks before replacing an existing file);
  - **Import**, from a vault `.json` file or pasted JSON. Orders merge by name: new ones are added, identical ones are skipped, and for differing same-named ones you choose Replace or Keep mine.
- **Shared export format,** identical in GridSense and Bases Toolbox: `{ "format": "property-orders", "version": 1, "orders": [ { "name": "...", "keys": ["..."], "unlisted": "after" } ] }`. A different format or version, invalid JSON, a missing name or key list, duplicate names, or an `unlisted` value other than `after` / `in-place` is rejected with a notice that names the problem.
- **Shared key-order helper** (`src/property-order.ts`). The single-note property editor's drag and Alt+↑/↓ reorder now uses it.
  - A property literally named `prototype` or `constructor`, or one with surrounding spaces, now keeps its place when a note is reordered or a reorder is undone.
  - Rebuilding the frontmatter no longer treats inherited object names (such as `toString`) as properties.
- Styles for the new window, using theme variables so it works in light and dark themes and at phone width.
- Housekeeping: the dev repository now tracks `pnpm-lock.yaml`, matching this repository's committed lockfile.
