## 0.27.0 — undo any logged operation from History, even after a restart

> **Untested:** this release hasn't been tried in Obsidian yet. It passed a type check, a production build and an independent code review, but nobody has clicked through it in a real vault. Back up your vault (or try it on a copy) before relying on it, and please report anything odd.

## Highlights

- **"Undo this" in History.** Each operation in a grid's History (🕘 history, or **Grid: edit history…**) now has an **undo this** button that puts back everything it changed, even after you've restarted Obsidian and the ⌘Z stack is gone.
- **Safe by design.** A value or note is only put back if it still holds what that operation wrote. Anything you've edited since is left alone, and the notice tells you how many changes were undone and how many were skipped.
- **Undo the undo.** Each "undo this" is recorded in History too, so you can undo it the same way.
- **Property reorders are recorded now.** Bulk reorders (from 0.26.0), their undo and redo, and moving a property in a note's property editor all appear in History and can be undone from there.
- **Vault-wide history.** Reorders run without a grid open are recorded at the vault root. The new command **Edit history for the vault root** opens that log.

## All changes

### 0.27.0

- **History window** (`src/history-log.ts`):
  - **undo this** on every entry of the full log. It is not offered in the narrower row, column or cell views, which show only part of an operation; those keep the per-value **restore** button.
  - Not offered on **add row** entries. Creating a note isn't recorded in the log, so undoing only its properties would blank the note and leave it. Delete the row instead (it goes to the GridSense trash).
  - Reorders are listed as `property order: a, b, c → b, a, c`. The header counts note reorders alongside value writes.
- **How "undo this" decides** (`revertEntry`):
  - A value is restored only if it still equals what the entry wrote. An empty value and a missing property count as different.
  - A value already back where it started is a silent no-op, so undoing twice is harmless.
  - A key order is restored only if the note's properties are still in the order the entry left them. A later manual reorder is left alone (`revertKeyOrder` in `src/property-order.ts`).
  - Notes renamed, moved or deleted since are counted and skipped.
  - When one operation wrote the same value twice, the changes are undone newest first, so the value ends at its original state.
- **Logging reorders:**
  - The bulk **Reorder properties** run is logged to the open grid's folder log, or to the vault-root log without a grid. Its ⌘Z, notice-button and command undo and redo are logged too, but only for notes they actually rewrote.
  - The single-note reorder in the property editor (drag or Alt+↑/↓) and its undo and redo are logged.
  - Logged orders are read from the note at the moment it is written, not from Obsidian's cache, which can lag right after a change.
- **New command:** "Edit history for the vault root (incl. reorders run outside a grid)".
- **Log format:** history lines gain an optional `orders` list (`path`, `before`, `after` key orders). Older log lines keep working unchanged.
- **Known limits:**
  - A property reorder still rewrites the frontmatter through Obsidian, so YAML comments inside the frontmatter are dropped and aren't brought back by undo.
  - The ⌘Z stack itself is still in memory only; History is the way back after a restart.
